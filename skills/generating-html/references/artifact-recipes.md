# Artifact recipes

Read the row(s) for the artifact you're building. These are the moves an agent tends to skip — the ones that separate a good version from a winged one. Build only the affordances the artifact actually needs.

## Native interactivity toolkit

You rarely need a framework or a CDN. The native toolkit covers most artifacts, accessibly and with less code:

- **Progressive disclosure:** `<details>`/`<summary>` for collapsible sections (file diffs, FAQs, long step lists). Keyboard-accessible and screen-reader-announced for free; rotate a CSS `::before` chevron on `details[open]`. Reach for this before hand-rolling an accordion.
- **Toggles / tabs / segmented controls:** native `<input type="radio">` or `checkbox` styled with `label:has(input:checked)` — selection state with zero JS, keyboard-navigable by default.
- **Tunable parameters:** on input, mutate a CSS variable — `document.documentElement.style.setProperty('--pad', v + 'px')` — and let the cascade repaint; no re-render.
- **Long scrollable artifact with sticky chrome:** give every jump target `scroll-margin-top` of at least the header's rendered height, or each TOC click parks the target underneath it. Build progress bars **block-level** — an inline `<span>` track has no box height, so a `height:100%` fill escapes and paints as a detached rectangle floating over the page — and clip with `overflow:hidden`, marking the track `role="progressbar"` with `aria-live="polite"`.
- **Stable demos:** seed any placement/shuffle from a tiny inline hash (e.g. FNV-1a) instead of `Math.random()`, so reload and "reset" return the same layout.
- **Re-render on input:** debounce with `requestAnimationFrame`, not a `setTimeout` guess. For `contenteditable`, intercept paste (insert `text/plain` only) and Enter so the markup can't corrupt.

**Exporting a result.** When the artifact's value is what the reader hands back, give it an export button that serializes state to JSON or an indented outline and copies it with a hardened clipboard helper (async Clipboard API → `execCommand('copy')` → visible-textarea fallback) — never a bare `navigator.clipboard.writeText`, which breaks on `file://` and in sandboxes. One export affordance per result; don't make the reader choose between redundant "copy as X" buttons. *Genuinely distinct* exports are fine — a config editor offering "copy diff" vs "copy full" serves two real needs.

## Recipes

| Artifact | Affordances that earn it |
|---|---|
| **Spec / plan / RFC** | Spine: title + one-sentence framing → context → constraints → approach(es) → mockups/diagrams → implementation steps (files to touch) → **open questions surfaced, not buried** → explicit out-of-scope list. Not every doc needs every section; a brainstorm may stop at approaches, an implementation plan may start at steps. For a large problem, produce a linked set (`01-context.html`, `02-options.html`, `03-implementation.html`) rather than one doc nobody reads end-to-end. |
| **Design prototype** | Real CSS and real motion, even when the production target is React Native or Swift — the translation is mechanical, the exploration is the hard part. Patterns: single-component stage surrounded by controls · variant grid (sizes × states × themes) · animation tuner with a replay button · side-by-side variants each labeled with its tradeoff · multi-screen flow strip. Show the resulting CSS live in a copyable code panel. |
| **Interactive playground** | Every parameter gets a labeled control with **its current value and unit shown next to it** — a slider with no readout is unusable. Defaults must be the user's *actual current values*, or they spend the first minute resetting. Preview updates live on input, never on a button press. Group controls under headers (Timing / Visual / Behavior) and include a Reset. For non-visual parameters (debounce, retry count, batch size), the "preview" is a synthetic visualization of the resulting behavior — a chart, a simulated event stream — not just the inputs echoed back. |
| **Throwaway editor** | **Pre-populate with the data the user already gave you** — never make them paste it again. Patterns: drag-and-drop board (Now/Next/Later/Cut with per-column counts, pre-sorted by your best guess) · form-based config editor (group by area, highlight changes, export only the diff) · dataset curator (big yes/no, running counts: "37 to review, 12 approved") · annotation tool · value picker. Add keyboard ergonomics past a handful of items: `j`/`k` to move, `1`–`9` to bucket, `enter` to confirm, with a `?` panel listing them. Export is the whole point — an editor without one is a dead end. |
| **Brainstorm / variant grid** | 3–6 cells, each rendering an **actual instance** of the option, not a description of it. Vary along several axes at once (layout × density × emphasis × tone; or register × length × etymology for naming) — if two cells could be described in the same sentence, collapse them and add something more contrasting. Label each cell with the tradeoff it makes ("fastest to ship, hardest to extend"), never "Option A". Equal cell sizes; unequal sizing implies a ranking. 3 → row, 4 → 2×2, 6 → 2×3. Don't pick a winner for the reader. |
| **Data explorer / dashboard** | Faceted filters (AND across facets, OR within a facet), updating live with no "Apply" button; active-filter count + "Clear all" always visible; row count always shown; detail drawer on row click; paginate past ~500 rows and say so explicitly ("showing first 500 of 12,408"); persist filter state in `location.hash` for shareable links. State plainly in the header that the **full** dataset is embedded — filters change the view, not the file, and a shared link ships every hidden row. Charts need axis labels and units; hand-rolled SVG beats a charting library for small data. |
| **Comparison / decision matrix** | Candidates as rows, criteria as columns; per-column weight sliders (normalize to 1.0) that live re-sort; pass/fail hard-requirement rows that disqualify outright; a verdict pane naming the winner; a sensitivity line — "*X wins if Performance ≥ 35%*" — showing what weight flip changes the outcome. |
| **Roadmap / timeline / Gantt** | Time runs left-past → right-future; a mandatory "Today" marker when the range straddles now; one fixed status vocabulary (On track/Shipped, At risk, Blocked, Planned, Cancelled) carried by shape+label, not color alone; dependency arrows only for hard cross-team handoffs; collapse to vertical stacked cards on mobile. |
| **ERD / schema explorer** | Table cards listing column name + type + PK/FK markers + nullability + indices; crow's-foot cardinality on FK lines (not text labels); click a table to highlight its relationships and fade the rest; name search; migrations as side-by-side before/after diff (added green, removed red, changed amber). |
| **Mind map** | Draggable nodes; double-click to edit; `Tab`=child, `Enter`=sibling, `Delete`=remove; pan + zoom; a layout toggle (tree / radial / vertical); export as indented outline, JSON tree, or a prompt to hand back to an agent. |
| **Slideshow deck** | `scroll-snap-type:y mandatory` + `scroll-snap-align:start` per slide; `→`/`space` next, `←` previous, `f` fullscreen, `n` toggles speaker notes kept in an `<aside>` per `<section>`. Sync `location.hash` so `#3` deep-links slide 3; an `IntersectionObserver` keeps the "N / M" counter honest. Headings at `clamp(40px,6vw,64px)`; body no smaller than ~24pt. **Content rules matter more than mechanics:** one idea per slide, ≤10 lines of code per code slide, ≤3 short bullets or split it, a recap slide naming the three takeaways, and no padding — a 15-minute talk is 12–15 slides. |
| **Testing / QA checklist** | Group into end-to-end flows (Flow → Phase → Step), never a flat 40-row list; derive every step from the actual diff and ticket thread — a step invented from a title is a guess wearing a checkbox, so flag any you couldn't ground as unverified; each step is one action with one **Pass** condition, an optional **Watch** fail-signal, and the exact command embedded as a copyable snippet; state is `pass / fail / blocked / skipped` with a notes field revealed on fail — a bare checkbox discards the only data worth collecting; sticky progress bar counting *resolved* steps (plus per-flow sub-bars) and an "All checks" appendix so nothing hides inside a step. |
| **Research report / explainer** | Spine: TL;DR a non-author can follow → why it matters now → substance in navigable sections → diagrams → annotated snippets → gotchas/surprises → the action edge (what's next, open questions) → **sources**. Cite concretely inline — "(commit a3f4)", "(Slack: #incidents, Tue)", "(Linear: ENG-1247)" — so a reader can verify a claim without asking. Lead with the recommendation in a decision memo; don't bury the lede. Synthesize rather than paraphrase, and don't hedge every claim. |
| **Code review / PR explainer** | Spine: PR identity → TL;DR → what changed and why (narrative, not a file list) → risk map → annotated diffs → concept callouts → test coverage → reviewer checklist. Severity by shape+label — `🔴 blocking` / `🟡 nit` / `🟢 nice`. Risk map up top (files sized/colored by change-volume × exposure, click to jump to the diff). Margin annotations sit *beside* the line they reference, ~40 words, link out for more — don't bury concerns in prose after the diff. **Mark sections you didn't review as skipped, honestly.** Don't restate the diff in prose; it's already there. |

## Anti-patterns across recipes

- Decorative visuals that carry no information — every diagram should say something prose can't.
- Burying open questions or key numbers in a flat wall of text instead of surfacing them visually.
- A wall of green checkmarks; reviewers stop reading by the third one.
- Building generic infrastructure for a one-shot artifact. Hardcode for the data you have.
- Filtering that needs an Apply button, or a slider with no value readout.
- Five options that are visually identical with one detail changed — that's parameter tuning, not exploration.
